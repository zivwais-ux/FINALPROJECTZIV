# מדריך שימוש והצגה למרצה

**האתר:** https://churn-pipeline-zivwais-uxs-projects.vercel.app
פתוח לכולם, בלי התחברות. עובד במחשב ובטלפון, במצב בהיר ובמצב כהה.

## מה יש באתר (תפריט עליון)
| דף | מה רואים | למה זה חשוב למרצה |
|---|---|---|
| **Overview** | הסיפור, נתוני ההרצה האחרונה, סיור מודרך, ו**טבלת דרישות הקורס** | נקודת הפתיחה. כל דרישה מקושרת לדף שמראה אותה |
| **Architecture** | תרשים המערכת, תהליך ה-RAG, וכל 9 הסוכנים עם התפקיד, הכלי והפרומפט | דרישות שיעור 1: מיפוי ה-RAG, זרימת הכלים והפרומפטים |
| **Data Analyst** | נטישה לפי פלח, חסרים, כפילויות, וחוזה הנתונים | Crew 1 והחוזה (סכמת הנתונים) |
| **Data Scientist** | השוואת מודלים, מטריצת בלבול, שער איכות, כרטיס מודל | הבונוס: מודל ML |
| **Briefing** | מקלידים `CustomerID` ומקבלים תדרוך מיידי: ציון, תוכנית שימור שנקבעה בקוד, הכללים מהמסמכים וחדשות חיות | הדרישה המרכזית: "מקלידים שם ומקבלים תדרוך" |
| **Briefings** | 23 תדרוכים שסוכן כתב, כולם תואמים לתוכנית | התדרוך שמשלב RAG וחיפוש ברשת |
| **Runs** | היסטוריית ריצות מ-Supabase, ודוח לכל תרחיש שבירה | הוכחה שהמערכת רצה ושהשערים עובדים |
| **Contract Checker** | לחיצה אחת שוברת את הנתונים, ורואים את השער עוצר | הדגמה חיה |
| **Code** | הקוד של ה-Flow, השערים, הוולידטור, ה-RAG, תוכנית השימור, החיפוש ברשת וה-guardrail | הקוד שמאחורי ההחלטות |

## הצגה של 5 דקות
1. **Overview (30 שניות):**
   - **הסיפור:** שינוי שקט מסנטים לדולרים הרס מודל במשך 5 שבועות.
   - **הפתרון:** שני crews עם חוזה נתונים שנאכף בקוד.
   - **טבלת הדרישות:** להראות אותה.
2. **Architecture (דקה):**
   - **התרשים:** סוכנים בסגול, שערים בקוד באדום.
   - **העיקרון:** "הסוכנים מחליטים, הקוד מחשב, והשערים לא LLM".
   - **פרומפט לדוגמה:** לפתוח פרומפט של סוכן אחד.
3. **Contract Checker (דקה, ההדגמה החזקה ביותר):**
   - **`clean_data.csv`:** ללחוץ. התוצאה PASSED.
   - **`unit_change`:** ללחוץ. התוצאה FAILED, עם "about 100x off, possible unit change", ו-Crew 2 לא רץ. זו בדיוק התקרית מהסיפור.
4. **Data Scientist (דקה):**
   - **הממצא:** כפילויות בנתונים ניפחו את PR-AUC ל-0.993. אחרי חלוקה נכונה התוצאה היא 0.864.
   - **הנקודה:** זה מראה בדיקה ביקורתית ולא רק הרצה של מודל.
5. **Briefing (דקה וחצי):**
   - **הדגמה:** להקליד `51809`.
   - **מה רואים:** ציון 0.95 (סיכון גבוה), ו-"The plan": פנייה בעדיפות 1 בטלפון, לסגור את התלונה לפני כל הטבה, שיחת היכרות ללקוח חדש, שובר משלוח חינם במקום cashback (לקוח COD), תקרות ואישורים. ליד כל החלטה הסעיף במסמך שממנו היא באה.
   - **מתחת:** "Why", הכללים שה-RAG מצא במסמכים, ו-"Market now", חדשות חיות מהיומיים האחרונים על השוק של הלקוח.
   - **מקרה שכדאי להראות:** להקליד `50013`. הציון נמוך, אבל הלקוח התלונן, ולכן התוכנית אומרת לפנות (עדיפות 2, דרך צוות התמיכה) ובלי הטבה. זו בדיוק טעות שסוכן עשה בעבר ("לא לפנות"), ועכשיו היא לא יכולה לקרות.
   - **השוואה:** ללחוץ על "agent-written briefing". אותה תוכנית בדיוק; הסוכן כתב רק את ההסברים ובחר כתבות רלוונטיות.
   - **המשפט להגיד:** "ההחלטות הן כללים, ולכן הן בקוד. הסוכן מסביר, ובדיקה בקוד דוחה הסבר שסותר החלטה או קישור שלא הגיע מהחיפוש."
6. **Runs או Code (30 שניות, אם נשאל "איך זה עובד"):**
   - **Runs:** כל תרחיש שבירה, והשער שעצר אותו.
   - **Code:** `gates.py`, ו-`retention_plan.py` (המדריך ומדיניות ההנחות כקוד).

## מה כדאי להגיד ביושר
- **החיפוש ברשת** הוא חדשות אמיתיות מ-48 השעות האחרונות, מ-Google News בלי מפתח, על שוק אמיתי במקום החברה הבדויה: מסחר מקוון בארה"ב.
- **המסמכים הפנימיים של Harbor & Vale סינתטיים.** הנתונים עצמם אמיתיים, מ-Kaggle.
- **התדרוך המיידי מורכב בקוד** מהמודל, מתוכנית השימור ומה-RAG, בלי LLM. תדרוכים שסוכן כתב קיימים ל-23 לקוחות, ונוצרים עם `uv run brief`.
- **החלטות השימור נקבעות בקוד ולא על ידי הסוכן.** כך הן תמיד תואמות למסמכים: `scripts/audit_briefings.py` מראה 23 מתוך 23 (לפני השינוי 18 מתוך 23).
- **החדשות אמיתיות אבל לא תמיד רלוונטיות:** בתדרוך המיידי לפעמים מופיעה כתבה כללית; בתדרוך שסוכן כתב הוא בוחר רק את הרלוונטיות.

## הרצה מקומית (למי שרוצה להריץ בעצמו)
```bash
uv sync
cp .env.example .env                 # OPENAI_API_KEY
uv run kickoff                       # כל ה-pipeline, כ-2 דקות
uv run python scripts/break_it.py    # 5 תרחישי שבירה
uv run brief 51809                   # תדרוך שסוכן כותב
uv run python scripts/audit_briefings.py   # בדיקה שכל התדרוכים תואמים לתוכנית
uv run web                           # האתר על http://127.0.0.1:5000
```
